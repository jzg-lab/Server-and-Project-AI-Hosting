# 可视化第一性原理与界面规则

- **状态**：第六轮全局/项目作用域确认
- **日期**：2026-08-09
- **适用阶段**：G0 / Map 原型

## 1. 先定义用户必须回答的问题

界面不是把资料放在屏幕上，而是让用户在最短时间回答一个问题：

| 作用域 / 视图 | 首要问题 | 图形回答 |
|---|---|---|
| 全局 / 全局业务网 | 我的业务网由什么组成，哪里需要注意？ | 业务统筹 Agent 在中心；第一层只显示项目；状态直接写入项目卡片和连线 |
| 全局 / 全局资源 | 哪些资源被共享，一个资源变化会影响谁？ | 共享实体只出现一次；集合视角盘点，反查视角展开使用项目和工作负载 |
| 项目 / 运行与流程 | 这个项目这一次怎样运行，它本应怎样工作？ | 默认显示只读运行事实；同一骨架显式切换到编辑草稿 |
| 项目 / 项目资源 | 这个项目拥有什么、引用什么？ | 项目边界内是私有资源，边界外是共享引用；共享实体跳到全局反查 |

首屏不是“只剩一张图”。按信息职责分成三层：

1. **关系层（中心图）**：回答“谁与谁有关、结构是什么”；
2. **信号层（四周小框）**：回答“整体是否正常、此刻发生什么、哪里要注意”；
3. **解释层（固定信息岛）**：回答“为什么、来源是什么、下一步能做什么”，但不覆盖中心图。

如果一个元素既不能回答首要问题，也不能补充必要判断，就不进入首屏。详情、来源、能力和操作只在选中节点或信号后出现。

## 2. 研究得到的可复用经验

### 2.1 信息可视化

采用 Shneiderman 的信息寻求口诀：**Overview first → zoom/filter → details on demand**。首屏先呈现关系全貌，缩放和选择用于聚焦；文本详情在固定信息岛中原地更新，不使用遮挡画布的抽屉。

视觉编码遵循 Bertin 的视觉变量和 Munzner 的嵌套模型：

- **位置**表示层级/归属，不用位置装饰；
- **大小**表示组织重要性（业务统筹 Agent > 项目 > 资源）；
- **连线样式**表示事实来源（实线=观测，细虚线=声明，幽灵线=期望）；
- **环颜色/缺口**表示健康与核验状态；
- **移动信号与脉冲**只表示真实的状态同步、告警上报或瞬时活动，不把它误写成静态结构。

状态页面还必须满足“扫一眼先判断、再读数确认、最后按需解释”的顺序：

- **先用前注意视觉变量表达状态**：位置、长度/填充、轮廓、图标和有限的状态色优先于长句；异常在稳定布局中自然浮现，不要求用户逐卡阅读。
- **数值必须带参照**：百分比同时给已用/总量或阈值；吞吐给方向与单位；load 给 CPU 核数参照；没有上限的量不画误导性的圆环。
- **一项状态只选一个主编码**：例如容量用水平填充、当前趋势用短 sparkline、离散健康用状态徽标；不为装饰同时堆仪表盘、环图、面积图和动画。
- **颜色只做加速器**：绿/黄/红/灰必须同时配合图标、形状或文字。数据过期/缺失使用灰色和断点，不伪装成绿色正常。
- **先比较、后细节**：同类 HOST 指标保持相同位置、尺度和阈值，便于横向扫视；精确来源、采样质量和解释在选择或展开后显示。

### 2.2 拓扑图、NOC 与态势感知

网络拓扑和可观测性产品的共同做法是把依赖关系作为主视图，并让节点状态直接改变连线或边界，而不是另起一张统计表。控制室/任务控制界面保留一个稳定的空间参照系，再把异常、流量和当前路径作为局部覆盖层。

因此本项目采用“稳定骨架 + 活动覆盖层”：

1. 项目和资源的空间位置在同一视图中保持稳定；
2. 运行事件沿关系路径移动或闪烁；
3. 选择一个节点才展开解释和操作；
4. 不用发光、数字雨或无语义 HUD 填充空白。

### 2.3 控制语义

Kubernetes 等控制平面采用“期望状态—实际状态—收敛”的模型。本项目借用这一语义，但不再设置泛化的全局“控制视图”：期望/实际差异只出现在具体流程节点、资源关系或操作请求附近。任何控制动作都是请求，只有收到外部回执并重新读取后才改变实际层。

### 2.4 Apple 式简化

参考 Apple 的 Purpose、Simplicity、Familiarity、Agency 原则：

- 顶部只保留品牌、三个职责明确的全局入口、当前项目局部导航和同步状态；
- 图占据舞台的绝大部分面积；
- 文字采用系统字体和短标签，次要内容渐进披露；
- 详情从选中节点映射到固定信息岛，位置稳定、无需开合、不阻塞地图；
- 动效只服务于状态同步、告警上报和直接交互反馈；周期动画必须有可解释语义、可以关闭，并支持 `prefers-reduced-motion`。

这里的“简单”不是删除上下文。在业务网、资源关系和项目投影等关系页面，中心图保持绝对视觉中心；左侧范围/筛选和固定选中详情可以作为辅助框架存在，但不能把画布压缩为表格或统计卡片矩阵。服务器状态页不是关系画布，允许用少量可比较的资源卡和条形编码作为主舞台。全局页把固定信息岛、业务统筹 Agent 最近操作和业务统筹 Agent 对话放在右侧；项目页把选中步骤放在流程图下方。项目卡默认只承担五项判断：**名称、定位、健康、活动、异常**；来源、共享边界和内部资源在选中后披露。

持续监控、健康和控制边界使用稳定的节点与线型；沿项目到业务统筹 Agent 移动的光点只表示周期状态同步，琥珀色光点只表示告警上报，未接入项目的虚线保持静止。禁止无语义旋转、漂浮和大面积呼吸光晕。

## 3. 统一视觉语法

```text
矩形节点层级：业务统筹 Agent > 项目 > 项目内资源 / 事件
实线：外部观测到的事实
细虚线：用户登记或外部声明的关系
幽灵虚线：期望关系（尚未收敛）
青绿色环：在线/已核验
琥珀色缺口：待核验/漂移/等待回执
灰色环：低活动但仍在监控
移动光点：状态同步或告警上报；停止后不改变静态拓扑
锁与边界环：访问规则和控制能力边界
```

颜色永远与形状、线型和文字同时出现，不能靠颜色单独传递含义。

## 4. 两层作用域的边界

### 4.1 全局层

#### 全局业务网（Overview）

- 默认打开；以全部 Business 的粗粒度状态和覆盖为主，提供唯一的“新建业务”主入口；
- Business 节点沿稳定位置分布，必要时只显示项目数量、覆盖、异常和新鲜度摘要；点击后再进入业务或具体项目上下文；
- 共享组默认不占据顶层画布，只在关系/权限覆盖层中出现且不复制资源；
- 业务卡常驻显示名称、定位、覆盖、活动和异常；没有足够项目观察时显示 unknown，不用 HOST 正常推导业务健康；详细事实在选择详情中显示；
- 右侧固定为业务统筹 Agent 工作台：顶部是压缩的当前焦点，中部是可按项目筛选的业务统筹 Agent 最近操作，底部是最多 4 个随焦点变化的快捷动作；
- 中心画布正下方是业务统筹 Agent 命令条，显示明确目标、输入框、发送和最近回执；完整会话按需在同一信息岛内展开；
- 可以拖拽、平移、缩放和恢复布局。

#### 全局资源（Global Resource）

- 默认显示 HOST、TechnicalProject、Deployment/服务和 ResourceEntity 的真实拓扑，所有 HOST 与非归档项目均可达；
- 可切换共享集合与影响反查；每个稳定资源实体只出现一次，并能展开全部使用项目、部署与服务；
- 可按层级聚合低层对象，但必须显示隐藏数量与展开依据；不承担 SSH 管理、服务器监控主面板或流程编辑；
- 点击项目节点可进入该项目的资源边界。

#### 服务器资产（Global Hosts）

- 独立展示 HOST；首屏主视觉是最近一次 CPU、内存、load、磁盘、IO、网络、uptime 等当前资源状态，数字、单位、参照、采样时间和 freshness 同时可见；
- 当前指标使用容易比较的进度条/容量条、短趋势和状态徽标，不用大段文字列表代替可视判断，也不使用无明确上限的装饰性仪表；
- 健康历史位于当前状态下方，使用较矮、稀疏、大圆角且能表达 gap 的时间带，只作为辅助上下文；
- 连接状态、Provider 覆盖、DeploymentCandidate 和最近发现属于可信度与管理信息，视觉层级低于当前资源状态；
- 入口使用 global/hosts，与共享资源集合和影响反查分开；
- 服务器操作只在选中的 HOST 信息岛中提供登记、重连、只读发现和证据查看；
- 连接成功、发现状态、证据新鲜度和业务健康分别显示，不用单一绿色状态替代它们。
- 不在服务器页放置 Business 看板、服务器—项目—服务空间关系画布或具体项目投影工作台。

### 4.2 项目层

#### 运行与流程（Run & Flow）

- 只在已选项目上下文中出现；项目名和流程名必须持续可见；
- 进入项目默认显示运行模式，而不是编辑模式；
- 编辑与运行使用同一张图、同一套节点位置；模式切换不能造成空间认知重置；
- 编辑模式突出结构、分支、闸门、恢复路径和版本差异；
- 运行模式只读，突出实际路径、当前步骤、耗时、结果与回执；
- 运行实例始终固定在启动时的已发布版本，正在编辑的草稿不能覆盖运行事实；
- 选择节点后，流程图下方的固定信息岛按当前模式显示配置项或运行事实；
- 流程图外另设项目上下文图，表达知识库、服务器、仓库、域名、凭据引用等外部依赖；这些对象不伪装成流程步骤；
- 项目上下文图下方保留完整运行轨迹，按时间显示步骤顺序、跳过/当前状态、耗时和外部回执。

#### 项目资源（Project Resource）

- 固定为当前项目，项目边界内显示私有资源，边界外显示共享引用；
- 同一资源只出现一次，多项目使用通过多条关系表达；
- 不在项目页混入全局共享集合切换器；
- 点击共享资源直接跳到全局资源反查，展示影响项目和工作负载；
- Deployment 和 ProjectTarget 显示具体运行目标，代码仓库只作为版本或文档引用，不生成开发工作区节点。

### 4.3 直接操控不变量

- 指针、节点和关联几何必须连续：拖动过程中每次指针更新都同步更新节点、连线、箭头、标签和状态信号；
- 松手只负责提交布局变更，不能成为首次更新连线的时机；
- 运行模式只读，只有总览节点和流程编辑节点可拖拽；
- 所有拖拽使用指针捕获并保留抓取偏移，避免节点跳到指针中心。

## 5. 原型验收标准

- 首屏 70% 以上面积由关系图或状态图占据；
- 中心图始终是第一视觉焦点，但首屏仍能直接读到覆盖、健康、活动和注意四类关键信号；
- 辅助信息不能形成统计卡片矩阵，也不能压倒中心画布；
- 用户能在 3 秒内指出业务统筹 Agent、各项目、需关注项目和当前活动；
- 用户能一眼区分全局层与具体项目层，并能看见当前项目名；
- 进入任何项目后首先看到只读运行事实和运行实例，不显示编辑工具箱；
- 运行与流程能一眼区分可编辑草稿与只读运行事实；
- 编辑/运行切换前后，流程节点坐标保持一致；
- 全局资源与项目资源有明确不同的标题、入口和图形问题；
- 项目资源能一眼区分私有资源与共享引用，并能跳转反查共享影响；
- 节点可选中，详情在固定信息岛中原地更新；全局工作台和项目详情都不遮挡画布；
- 全局工作台可按项目筛选业务统筹操作，并可在画布下方针对当前目标输入问题；快捷动作结果回流最近操作；
- 快捷动作必须标注观察/准备/执行语义；观察与幂等请求可直接触发，外部副作用请求先展示预览和确认；尚未接入的能力显示待接入状态；
- 项目运行页能同时看见流程图、流程外部依赖与完整运行轨迹，三者语义不混用；
- 服务器资产页能分别读出 HOST connection state、Provider discovery state、Deployment freshness、Project Agent cycle 和 Business health；
- 缩放、拖拽、键盘导航和减少动效偏好均可用；拖动时箭头和标签连续跟随。
- 状态流光点必须沿项目与业务统筹 Agent 的实际连线移动；关闭状态流或启用减少动效后停止显示。
