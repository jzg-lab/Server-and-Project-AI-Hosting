# 项目运行与流程、双层资源视图整合方案

- **状态**：已确认并实现
- **版本**：1.2
- **日期**：2026-08-09

## 1. 边界先行

TechnicalProject 是流程和私有资源的运维边界，Business 是跨项目的语义分组。第一性原理是：没有脱离项目语境的流程实例，也不能从单台 HOST 直接推出完整业务。因此先确定作用域，再回答问题：

```text
个人业务网
├─ 全局业务网
├─ 全局资源
├─ 服务器资产
└─ 项目
   ├─ 运行与流程（进入项目默认页，默认运行模式）
   └─ 项目资源
```

| 作用域 | 页面 | 唯一问题 | 中心图 |
|---|---|---|---|
| 全局 | 全局业务网 | 业务由什么组成，哪里需要关注？ | 业务统筹 Agent 与全部项目 |
| 全局 | 全局资源 | 哪些资源被共享，一个资源变化会影响谁？ | 共享集合 / 资源影响反查 |
| 全局 | 服务器资产 | 哪些 HOST 已接入、发现覆盖如何、部署候选有哪些？ | HOST 状态与 Deployment 列表 |
| 项目 | 运行与流程 | 该项目这一次怎样运行，它本应怎样工作？ | 同一张可观察/可编辑流程图 |
| 项目 | 项目资源 | 该项目拥有什么、引用什么？ | 项目私有资源与共享引用 |

独立“运行页”与泛化“控制页”继续移除。运行是已发布流程版本上的事实覆盖层；控制能力进入具体步骤、资源关系或操作请求的上下文中。

## 2. 项目入口与默认状态

点击侧栏项目、全局业务网中的“进入项目流程”或项目快捷键时，系统必须执行同一组状态转换：

```text
scope = project
activeProject = clickedProject
view = workflow
workflowMode = run
```

默认运行而不是默认编辑，原因只有一个：进入项目的首要任务是判断“现在发生了什么”，改变结构是低频且有版本后果的显式动作。运行模式显示实例、路径、当前步骤、耗时和回执；用户选择“编辑”后，才显示工具箱、保存草稿和发布能力。

项目作用域内始终显示项目身份条，提供两个局部入口：

```text
[Hermes · 消息网关与 Agent]     [运行与流程] [项目资源]
```

## 3. 流程框架与运行实例合一

### 3.1 第一性原理

```text
运行实例 = 已发布流程版本 + 本次执行事实
```

因此只保留一张流程图，通过模式切换改变权限与叠加信息：

| 维度 | 运行模式（默认） | 编辑模式 |
|---|---|---|
| 图结构 | 只读 | 可添加、连接、删除、拖拽 |
| 主要信息 | 实际路径、当前步骤、耗时、结果、回执 | 步骤、分支、闸门、恢复路径 |
| 版本对象 | 实例启动时的已发布版本 | 当前草稿 |
| 底部信息 | 实例选择与运行摘要 | 未发布变更摘要 |
| 节点详情 | 时间、输入输出摘要、状态、来源 | 输入、能力、条件、失败策略 |

模式切换时节点坐标和连线骨架保持一致。`RUN-028` 若由 `v3` 启动，就永远在 `v3` 上解释；发布 `v4` 只影响后续新实例。

### 3.2 页面结构

```text
[Hermes 项目作用域]                         [运行与流程] [项目资源]

Hermes / 消息处理流程 / RUN-028 · v3         [编辑 | 运行]

┌────────────────────────────────────────────────────────────┐
│ [运行实例 · 只读事实]                                      │
│                                                            │
│      触发 ── 理解 ── 路由 ── 调用能力 ── 验证结果           │
│                      └── 人工确认 ───────┘                  │
│                                                            │
│                                      [节点信息岛·按选择更新]   │
└────────────────────────────────────────────────────────────┘

运行模式底部：RUN-028 · v3 · 当前步骤 · 已运行时间
编辑模式底部：未发布变更数 · 当前运行实例仍固定使用 v3
```

流程图下方按固定顺序补足三类信息，避免用抽屉把它们叠在主图上：

```text
1. 当前步骤信息岛：选中节点的定义或本次运行事实
2. 项目外部上下文：知识库、HOST、Deployment、部署版本、域名、凭据引用与共享资源
3. 项目运行轨迹：触发时间 → 每一步 → 跳过/当前状态 → 耗时 → 外部回执
```

项目外部上下文与流程路径必须分开。流程图只表达因果步骤；知识库、服务器、仓库等是步骤调用或依赖的已有对象，不得画成流程节点。运行轨迹则是一次实例的时间序列，不改变流程定义。

## 4. 资源分成全局与项目两个作用域

### 4.1 全局资源

全局资源不显示项目私有对象，只提供两个镜头：

1. **共享集合（默认）**：每个共享资源实体只出现一次，用于盘点健康、凭据引用、共享范围和待核验状态。
2. **资源反查**：将一个共享资源置于中心，展开全部使用项目与工作负载，用于判断故障或变更影响。

点击共享集合中的资源直接进入反查。点击项目节点则进入该项目的项目资源页。

### 4.2 项目资源

项目资源固定绑定当前项目，不再提供全局镜头切换器：

- 项目边界内：项目私有资源；
- 项目边界外：该项目引用的共享资源；
- 连线：项目如何使用对应资源；
- 空项目：明确显示“尚未登记项目资源”，不借用其他项目数据填充；
- 点击共享引用：跳到全局资源的对应资源反查。

同一服务器、域名、仓库或知识库始终只有一个实体；多个项目使用它时只增加关系，不复制资源。

### 4.3 服务器资产

服务器资产页面使用 global/hosts，独立承担 HOST 登记、连接状态、Provider 能力、DeploymentCandidate、最近观测和证据新鲜度。它不替代全局资源的共享集合/影响反查，也不直接展示业务健康。

选中 HOST 或 Deployment 后，固定信息岛提供登记、重连、只读发现、证据查看和跳转项目入口。服务器服务、容器和部署的写入控制仍由后续独立能力规格处理。

## 5. 拖拽与连线的连续反馈

Apple 式直接操控要求“指针和内容一起移动”。拖拽节点时只更新节点、等松手后重绘连线，会让图的空间关系短暂失真，因此不符合本项目的交互不变量。

每一次 `pointermove` 必须同步完成：

1. 更新被拖节点坐标和 `transform`；
2. 找到全部入边和出边；
3. 根据节点边界重新计算锚点和贝塞尔路径；
4. 更新箭头所在 `path` 的 `d`；
5. 更新连线标签位置；
6. 状态光点继续引用同一个路径 ID，自然沿新路径运行。

`pointerup` 只提交布局变更和草稿计数，不承担首次几何更新。总览节点可拖拽；流程节点只在编辑模式可拖拽；运行模式保持只读。

## 6. 全局业务网的同步调整

- 顶层仍只显示业务统筹 Agent 和项目，不把服务器、域名、代码或共享组塞进第一层。
- 画布右侧固定为业务统筹 Agent 工作台，不再从画布边缘打开抽屉。
- 工作台顶部是压缩的当前焦点；“业务统筹 Agent 最近操作”位于中部并支持按项目筛选；底部是最多 4 个随焦点变化的快捷动作。
- 业务统筹 Agent 对话输入移到中心画布正下方，目标作用域、输入、发送和最近一条回执在同一命令条内；完整会话按需展开。
- 单条固定表达：时间、动作、对象、结果。
- 快捷动作只从当前作用域可用能力生成，至少标注观察/准备/执行模式；每次触发都回写同一条最近操作记录，不另造执行状态面板。
- 项目自身任务、服务事件和节点运行事实只进入对应项目的运行模式。
- 业务统筹 Agent 对话只表达本地会话和结构化请求，不因输入文本直接改写项目、流程或资源。

### 6.1 为什么不用抽屉

抽屉会产生三个额外问题：用户必须记住它是否打开、详情会遮挡主图、选中对象与详情位置不断变化。固定信息岛只做一件事：把当前选择映射到稳定位置。它在全局页位于右侧业务统筹 Agent 工作台顶部，在项目与资源页位于主图下方；没有开合状态，也不挤压或覆盖节点。

## 8. 页面状态与 URL

Hash 必须同时保存作用域、视图与当前项目，使刷新后仍回到同一语境：

```text
#scope=global&view=world
#scope=global&view=resource
#scope=global&view=hosts
#scope=project&project=hermes&view=workflow
#scope=project&project=hermes&view=resource
```

快捷键：

- `1`：全局业务网；
- `2`：全局资源；
- `3`：当前项目运行与流程，并回到运行模式；
- `4`：当前项目资源。

## 9. 实现职责

```text
renderWorldView()       → 全局：业务统筹 Agent 与项目
renderHostsView()       → 全局：HOST 连接、Provider 覆盖与 Deployment
renderWorkflowView()    → 项目：同一图的运行/编辑模式
renderResourceView()    → 按 scope 渲染全局共享/反查或项目边界
selectionCard()         → 按视图和选择对象更新固定信息岛
renderCoordinatorChat()→ 全局画布下方的业务统筹 Agent 命令条与最近回执
renderQuickActions()   → 全局右侧的上下文快捷动作
renderProjectContextOrbit() → 项目流程外的资源/知识上下文
renderRunTimeline()     → 项目运行实例的完整时间轨迹
```

## 10. 验收标准

- 全局导航包含“全局业务网 / 全局资源 / 服务器资产”；流程入口只在项目作用域出现。
- 点击任意项目默认进入运行模式，显示运行实例版本，编辑工具箱不可见。
- 运行/编辑使用同一节点坐标；编辑可拖拽、新增、保存草稿和发布。
- 拖动总览或流程节点时，关联箭头、标签和状态信号连续跟随。
- 全局资源默认显示共享集合，并可切换影响反查。
- 服务器资产页能区分 connection_ready、discovery_partial、证据过期和待确认 DeploymentCandidate。
- 项目资源只显示当前项目边界；空项目不借用其他项目的数据。
- 点击项目中的共享资源进入全局影响反查。
- 全局画布右侧完整显示当前焦点、业务统筹操作和上下文快捷动作；业务统筹操作可按项目筛选。
- 业务统筹 Agent 命令条位于画布正下方，目标作用域清晰，输入和最近回执在首屏可见。
- 快捷动作最多显示 4 个，点击后在最近操作中留下结果记录；观察/准备请求不伪装成外部写操作。
- 项目运行页在流程图下显示固定步骤详情、流程外部依赖与完整运行轨迹。
- 详情使用固定信息岛，不再出现遮挡画布或需要记忆开合状态的抽屉。
- `896px` 与 `560px` 宽度无横向溢出；减少动效偏好下停止非必要动画。
- URL Hash 能准确恢复作用域、项目和视图。
