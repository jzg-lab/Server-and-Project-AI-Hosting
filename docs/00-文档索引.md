## 文档目的

本项目首先是一个**可视化管理工具**：把已有服务器、Docker/Compose 项目、资源及其关系转换成可查看、可整理、可修改、可确认和可追踪的项目网络。现有前端画布与交互是保留基线，当前开发只补齐真实数据、管理闭环和必要的部署能力。

## 当前开发顺序

以下顺序是依赖关系，不是可任意并行堆功能的清单：

1. **冻结现有视觉基线**：不重做已确定的布局、画布、信息岛和主要交互。
2. **接通最小真实 API**：建立 `HttpDataSource`，让同一套节点/边契约同时服务 Fixture 与真实后端。
3. **取得真实事实**：登记一个 Linux HOST，通过 SSH 账号密码（默认）或 SSH Key、主机指纹确认和固定只读 Provider 取得 Docker/Compose 及其他部署证据。
4. **先把事实画出来**：确定性规则先生成可编辑图草稿；即使模型未配置或调用失败，用户仍能看到扫描结果。
5. **完成可视化管理闭环**：用户可在图和信息岛中更名、移动、合并、拆分、忽略、确认并保存本地投影。
6. **再加入轻量 Agent 辅助**：只做归类建议、关系解释、缺失问题和可编辑补丁，不直接发布事实。
7. **补齐重新扫描与发布门槛**：显示来源、新鲜度和差异；完成单一所有者登录、HTTPS、秘密边界、失败恢复与审计后才对互联网发布。

第 4–5 步是最早的用户价值证明；第 6 步不能成为第 4–5 步的运行前置条件。

## 当前共识

### MVP-1 产品主语

- 用户首先管理的是**项目、服务、容器、网络、卷、文档及其关系**，不是 Agent 组织架构。
- 当前 UI 是保留基线；新能力通过真实数据源、状态和信息岛增量加入，不重写页面。
- 全局业务网和项目资源图是首批真实数据页面；流程运行、跨项目责任网络和复杂治理不阻塞 MVP-1。
- 扫描事实、系统确定性映射、Agent 建议和用户确认是四种不同状态，界面与存储不得混淆。
- 用户确认后才发布本地项目投影；本地投影不代表外部项目或基础设施被创建或修改。
- 服务器上直接发现的是 Deployment 和资源；业务、TechnicalProject 与 Business 关系来自用户确认，Agent 只提出带证据的建议。
- HOST 属于全局基础设施层；服务器连接/发现管理与全局关系投影分开。
- `global/world` 不把 HOST 作为业务首屏；`global/resource` 通过 topology/shared/impact 三种 lens 让所有 HOST、TechnicalProject 和明确资源关系可达，但不放凭据、重连或扫描控件；这些管理动作只在 `global/hosts`。
- 左侧四类入口职责固定：全局业务网是全部 Business 的粗粒度统一看板；全局资源是 HOST、项目、Deployment/服务及资源关系；服务器页以当前资源状态为主、紧凑健康历史为辅；其下的项目投影只展开一个具体 TechnicalProject。不得在服务器页复刻资源关系画布或项目投影工作台。
- 当前已能按 HOST 手动采集或显式配置 interval schedule 来刷新当前资源快照，并从 schema 11 上线时起保存 CPU/内存/load/磁盘/网络/uptime/进程的 typed raw 样本；不从旧 `monitoring_current` 伪造过去历史。schema 12 的 H3b 代码按 UTC 固定边界生成 hour/day rollup，周期 compactor 在启动及配置 tick 上运行，`raw/hour/day/auto` 返回单一实际 resolution 与 rollup 统计。schema 13 的 H3c 已记录 schedule/policy provenance、固定 run policy revision、同一 run 健康评价和 24h/7d/30d UTC 时间带；破坏性 retention 仍默认关闭，ProjectTarget/service/port、Prometheus、告警和受控操作后置。
- CodeWorkspace 不属于运维核心对象；代码修改由专用开发 Agent 负责，部署只保存版本元数据。

### 技术入口与辅助能力

- `APP_HOST` 运行系统；MVP-1 默认通过 SSH 账号密码连接一个 Linux `TARGET_HOST`，也支持用户明确提供的 SSH Key。
- HOST 连接只以网络可达、SSH 认证成功并能读取 Linux 身份为准；Docker/Compose 未安装或权限不足属于附加发现结果，不得降级为 SSH 连接失败。
- 首次连接由服务端取得主机指纹，界面展示并由用户确认；发现器只执行固定只读动作。首版账号密码登录支持标准 SSH Password Authentication，以及常见的“单密码 Keyboard-Interactive/PAM”流程；系统不扫描本机或 APP_HOST 的私钥集合，不盲试多把私钥；多因素/MFA、多轮交互、SSH Agent 和“密码登录后安装托管公钥”后置。
- Docker/Compose 与白名单项目文档是首批事实来源；事实必须带来源、观察时间和失败状态。
- 确定性规则必须能独立产生图草稿；Agent 使用 OpenAI 兼容的 URL、Key、Model 做可选增强。
- Agent 输出始终是建议或问题；模型不可用时，扫描、图草稿、人工编辑和确认仍可继续。
- Docker/Compose 是可选 Provider；连接成功、发现状态、证据新鲜度和业务健康必须分别显示。
- 后端采用 Rust/Axum 模块化单体、SQLite WAL、REST 快照/命令、SSE 变化通知和 OpenAPI 生成类型。

### MVP-1 明确排除

- 多 Agent 协作基础设施、每项目独立 Agent、`ResponsibilityContract` 和完整 `ProjectPulse`；
- Docker/服务器/域名/账号修改，以及暂停、取消、改向等外部控制动作；
- 多用户组织、复杂 RBAC、多 HOST 编排、插件市场、图数据库和通用工作流引擎；
- 把前端原型中已有的每个按钮都做成真实后端能力。
